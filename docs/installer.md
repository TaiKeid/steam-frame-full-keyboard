# Installer

A window that installs, updates, downgrades, reinstalls or removes Full Keyboard without a terminal, and sets it up on a first install. It first installed 0.16.0 on a Steam Frame, through its wizard, on 2026-11-10.

The installer carries no package. It lists the stable releases from 0.16.0 on, the first that understands every wizard choice, newest first and the newest chosen. It downloads the chosen one with `update_helper.py --installer-fetch`, which checks it the way the [in-app updater](updates.md#verification-and-installation) does: HTTPS to the project's GitHub releases only, the exact `SHA256SUMS` entry and GitHub's digest, a safe unpack and the package's own checks. The release's `install.sh` then installs it, and `uninstall.sh` removes it.

## Screens

- **Home:** the keyboard on a lighter backdrop, its name, **Install** with a version list beside it, and the chosen version below. With a version installed, it says which, the button says what the chosen version does to it, **Update** for a newer one, **Downgrade** for an older one and **Reinstall** for the same one, and **Uninstall** sits below. The title over the progress bar says the same. Uninstall asks first, with **Keep my settings** on by default. The list shows the eight newest versions.
- **Setup:** the keyboard slides up and fades while the progress bar fills above a card. A first install shows its pages there while it downloads: Replace the native keyboard, swiping, typing suggestions, Pull for Shift, Use the numpad and, for 0.18.0 and newer, Streaming support. An older version doesn't have that feature, so it gets five pages and Finish lists five answers. Each has a picture of its feature on the left, playing in a loop, and its question on the right, Yes or No, Yes by default. Answered No, the picture dims; the numpad's shows the keyboard with or without it instead. Choosing doesn't advance; Back and Next do, and pages slide and fade like a carousel, with a dot for each along the bottom. The Streaming support page stays at No, dimmed, with the reason under it, when Replace the native keyboard was answered No.
- **Finish:** lists the answers and waits, with a spinner on Finish and a ring that fills, until the install is done. On a first install it saves the choices with the keyboard's own settings code, the same code Settings uses. With replacement on, it also sets up Start with SteamOS, starts the service and shows the keyboard. With [Streaming support](streamed-games.md#through-steams-own-streaming-streaming-support) chosen, it sets that up too. If the running Steam was started without it, a **Restart SteamOS** box shows under the badge, unticked: ticked, Finish restarts SteamOS instead of opening the keyboard, which then starts with SteamOS. Without it, Streaming support begins the next time SteamOS restarts. The box is not shown when no restart is needed. If Streaming support cannot be set up, Finish says so and offers **Finish without it** beside **Try again**; it can be turned on later in Settings. Back works until Finish is pressed. Updates, downgrades and reinstalls skip the wizard, keep settings as they are, and close on Finish, as an update in Settings does. A downgrade to a version older than 0.18.0, which knows nothing of Streaming support, also takes away its setting for Steam's start and points the library's link at Steam's own; the saved choice stays, so updating again sets it up again.

A keyboard that is running, also as the Start with SteamOS service, is stopped before installing, as `uninstall.sh` stops it. Steam's keyboard takes over meanwhile, and the service starts again afterwards. The interface follows the system language, as the keyboard does; its text is in the `installer.*` keys of `locales/`. The look comes from the keyboard's own drawing of cards, buttons and wells (`include/framekeyboard/paint.hpp`) in the Graphite theme, and every other colour is mixed from that theme's. The pictures use the keyboard's own picture and keys drawn like its keys; Pull for Shift's moves the legends as the keyboard does. Buttons go down under a press as keys do. The window has no close button of its own: KDE's title bar and Gamescope's app bar close it.

## Simulation

`--simulate` downloads, writes and starts nothing: each task only takes time. Host builds have it in `build/host/framekeyboard-installer`. The simulator preset builds the keyboard only, so a copy in `build/simulator/` is as old as the last time its `framekeyboard-installer` target was built. Versions before 0.18.0 have no Streaming support page; list 0.18.0 to see it:

```sh
build/host/framekeyboard-installer --simulate --releases 0.18.0,0.17.0
build/host/framekeyboard-installer --simulate --installed 0.16.0 --fail download
build/host/framekeyboard-installer --simulate --releases 0.18.0 --language ja --tour /tmp/installer-tour
```

`--installed` pretends a version is installed, `--fail` fails one task (`releases`, `download`, `install`, `uninstall`, `finish`, or `streaming` for Finish while Streaming support is chosen), `--streaming-active` pretends Steam already has Streaming support's setting so no restart is offered, `--speed` runs tasks faster, and `--tour DIR` saves every screen as PNG and exits: each page's picture at a telling moment, a page mid-turn, and controls with the laser on them and held down. A tour takes about twenty seconds, as the install is slowed to let the pictures play.

The window repaints only when its picture changes: every frame through a transition and while a wizard page's picture plays, thirty times a second for a spinner, and not at all on a screen where nothing moves. The card, the stage and Home's keyboard with its shadow and reflection are drawn once and reused.

## AppImage

Every release carries it as an asset, built by `scripts/package.sh` ([releasing](releasing.md#package-and-publish)). `scripts/installer-appimage.sh` builds `out/installer/Full_Keyboard_installer-aarch64.AppImage` with a `SHA256SUMS` file, from the `frame-arm64-release` preset and the stable sysroot. It needs `FRAMEKEYBOARD_SYSROOT`, `FRAMEKEYBOARD_APPIMAGETOOL` (appimagetool 1.9.1, as for the [simulator](simulator.md#appimage)) and `FRAMEKEYBOARD_APPIMAGE_RUNTIME`, the aarch64 runtime of [AppImage/type2-runtime](https://github.com/AppImage/type2-runtime) (release 20251108, SHA-256 `00cbdfcf917cc6c0ff6d3347d59e0ca1f7f45a6df1a428a0d6d8a78664d87444`). That runtime needs only FUSE 3, which SteamOS has; older runtimes need `libfuse.so.2`, which it lacks. The image carries our `LICENSE` and the runtime's ([third-party sources](../third_party/README.md#appimage-runtime)).

On the Frame, a downloaded AppImage doesn't open from the browser's download list. Open its folder in Dolphin, which also works in Game Mode, and double-click it. The first time, KDE asks whether to launch it and whether to trust it, and then makes it executable.

## Testing unpublished releases

`FRAMEKEYBOARD_INSTALLER_LOCAL=1 scripts/installer-appimage.sh` builds a test installer instead, `out/installer-local/Full_Keyboard_installer-local-aarch64.AppImage`. It is never a release asset. Besides GitHub's releases, it offers the release packages in its own folder, such as `framekeyboard-0.18.0-aarch64.tar.gz` built by `scripts/package.sh`, and installs those from there, with or without a network. A `SHA256SUMS` beside them must list each one it finds; without one, they are taken as they are. Each is then unpacked and checked as a download is. The same works from a build tree with `framekeyboard-installer --local-packages DIR`.
